# External ingress audit implementation — 2026-09-16

The supplied v3.73 audit was applied while integrating published main (`fc1f9913`) with preserved local changes. The release candidate retains the newer single-task import/export and schema-19 functionality. Publication and validation status are recorded in [VALIDATION.md](VALIDATION.md).

## Finding disposition

| Audit items | Implemented production behavior |
| --- | --- |
| 1 | Import stream is read directly with an API-26-compatible bounded loop; no nullInputStream or SequenceInputStream. Settings imports on the IO dispatcher. |
| 2, 4 | Webhook request and header lines are byte-bounded while reading. Tokens are rejected above 4096 UTF-8 bytes before constant-time comparison. |
| 3, 19 | New webhook triggers receive 256-bit random tokens; legacy blank tokens cannot dispatch. Details offers a review/regenerate path. Paths are decoded and checked for ambiguity/traversal; configured methods are enforced. Concurrent handlers, request counts, aggregate headers and a total read deadline are bounded. Rejection counters are implemented. |
| 5, 7 | Details owns enable/rotate/revoke/share and token-bearing shortcut URLs. A valid custom-scheme link always requires confirmation; invalid/tokenless links navigate to review only. Confirmation reloads the task and rechecks its token, including force execution. This implements the audit's safe custom-scheme alternative; verified HTTPS App Links were not invented without an owned domain. |
| 6 | deepLinkToken is transient in portable serialization and separately persisted in Room. Webhook tokens are also removed at export and import. |
| 8, 9, 10 | Domain HttpAccessPolicy is the shared HTTP permission rule. Builder hints, aggregation (including exit behavior) and runtime use actual config. Local access defaults off; enabling it requires API-37 permission and is exposed with review text in the editor. |
| 11, 12, 13 | HTTP DNS failure is closed. Every A/AAAA answer is checked, including CGNAT and IPv6 unique-local. The transport is pinned to the validated answer set, disables proxies and connection reuse across hops, and preserves normal TLS certificate/hostname verification. |
| 14, 15 | Product policy is deliberately HTTPS-only, including local services. Redirects are explicit, capped and revalidated. Scheme comparisons ignore case, and the manifest explicitly disallows cleartext. |
| 16 | Responses are bounded at 128 KiB. Oversize is an action failure with an empty body; output includes truncated/contentType/finalUrl/bytesRead. |
| 17 | Stream/text limit: 4 MiB; lexical scan bounds JSON depth, tokens and strings before deserialization; typed quotas cover task metadata, actions, triggers, constraints, config keys/values, end configs and maintenance dependencies. |
| 18 | MainActivity separates run-task links from shared-task imports. Shared imports accept only ACTION_VIEW content/file URIs with the supported MIME/extension contract; other schemes never reach the content resolver. Full and single-task imports share bounded preflight. The exported save target accepts typed content streams and rejects filesystem-path extras. |
| 20 | CI audits all production app/core/feature source manifests plus the merged release manifest against exact component/known platform permission pairs. Test/demo manifests are not packaged into the app. Widget receivers are non-exported. Arbitrary nonblank permissions do not pass the audit. |
| 21 | Schema 19 is generated by Room; migration 18→19 adds a nullable capability column. Dedicated and representative 1/12/16/18→19 migration tests were added. Original historical exported schemas 2 and 13 do not exist in the working tree or available Git history; they were not fabricated. The old→19 chains exercise those intermediate migrations without requiring invented historical hashes. |
| 22 | Elevated action warnings contain only a stable failure label and action enum; no configs, user-supplied keys or result messages. |

## Regression coverage

- ExternalIngressIntegrationTest: real URI parser → repository → review/confirmation → revalidated execution; tokenless/invalid/rotated/revoked cases; API-26 bounded import and disabled persistence.
- WebhookRequestGuardTest: real loopback socket oversized line without newline, canonical request through production matcher, ambiguous headers and aggregate bounds.
- HttpUrlPolicyTest: mixed public/private DNS answers in both orders, unresolved answers, local ranges and case-independent HTTPS policy.
- SecureHttpTransportTest: real TLS endpoint, pinned DNS, response metadata, oversized response and downgrade rejection.
- MigrationTest: 18→19 preservation and representative historical chains.
- BackupManagerTest and HttpPermissionWiringTest: portable capability exclusion, parser/model quotas and actual permission aggregation.
- FrameworkPermissionGatesTest and Python manifest audit tests: signature-level permissions and rejection of arbitrary gates.

## Product changes

Existing HTTP-only actions must use HTTPS. Legacy webhook callers must be updated with a newly generated token. Tokenless shortcuts open details; enable access and recreate/share a shortcut for confirmed execution. Rotating/revoking tokens invalidates previously issued links. Arabic and English security copy is provided; other locales currently use English for new copy.
