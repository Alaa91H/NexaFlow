# NexaFlow: مواصفات إدارة وكلاء الذكاء الاصطناعي وتوسعة الأتمتة

الحالة: برنامج تطوير مقسم إلى مراحل. المعلومات التي تصف الموجود أدناه فُحصت في الفرع عند c664c54b. بقية الأقسام متطلبات وتصميم مقترح ولا تدعي أنها منفذة.

## 1. الهدف

تتيح NexaFlow للمستخدم إنشاء أكثر من وكيل مستقل، وتحرير تعليماته ومزوّده ونموذجه وقدراته وأدواته وموافقاته وميزانيته وجدول تشغيله وذاكرته؛ ومتابعة كل تشغيل وإيقافه أو استعادته بأمان. توسع المحفزات والإجراءات بطريقة تحافظ على بيانات المستخدم الحالية، وتعرض تحريرا تخصصيا واضحا لكل حقل ولكل عملية، وتبين متطلبات الجهاز والصلاحية والمرافق قبل الإعداد.

المحرك الحالي يظل المالك الوحيد لجدولة الأتمتة والتحقق والتنفيذ وإعادة المحاولة والاسترجاع. الموفّر يجلب اقتراح النموذج فقط. كل إجراء مكتوب يمر عبر التفويض وخدمة الأوامر وفاحص القدرة والمخطط الحالي.

## 2. تقسيم التسليم

العمل عدة أنظمة مترابطة، وتسلم على دفعات مستقلة:

1. استكمال T20 إلى T28 من خطة الفرع الحالية، إصلاح توافق استدعاءات أدوات الموفّرات واختبارات الدمج، وبعدها دمج الفرع.
2. إدارة الوكلاء داخل التطبيق: تعريفات دائمة، محرر، سياسة أدوات وبيانات، تشغيل وميزانية وموافقة وإلغاء وسجل.
3. أساس العقد القانونية للأتمتة: تحرير الحقول typed، ومسار دائم وموثوق للعقدة القانونية التي لا تملك تعدادا قديما.
4. توسع عائلات المحفزات والإجراءات المحلية في دفعات من النوع إلى المحرر فالمخزن والمحرك والاختبارات.
5. موفّرات الجهاز والخدمة المرافقة والإضافات، كل منها بمتطلبات قدرة وصلاحية وهوية واختبارات مستقلة.
6. إتمام مصفوفة القياس والإتاحة والتحقق على الأجهزة المطلوبة قبل ادعاء دعم عام.

## 3. خط الأساس الفعلي

كان خط الأساس يحتوي 57 نوع TriggerType و176 نوع ActionType. أضافت موجة الاتصالات أربعة إجراءات متوافقة إضافية (CALL_BLOCK_SILENT وCALL_REPLY_WITH_SMS وSMS_REPLY وSMS_BLOCK_INCOMING)، فأصبح الإجمالي 57/180 مع بقاء الأنواع القديمة دون حذف. يسجل CanonicalIdentityRegistry 134 هدفا و46 عملية و12 شرطا؛ هذه مفاتيح تسجيل وليست 134 ميزة مكتملة ولا جميع توليفات الهدف والعملية.

لا يسمح المسار القانوني بعدُ بالتعريفات الجديدة اعتمادا على NodeSchema وحده. يبنى AutomationNodeCatalog من التعدادات القديمة؛ وV3 يحتفظ بأعمدة المصدر القديمة؛ وCanonicalWorkflowV3ReadMapper يعيد حل المصدر إلى التعداد؛ وCanonicalCompatibilityActionDispatcher يطلب Handler حسب تعداد الإجراء. ولذلك يتطلب أي نوع جديد مسار كتالوج ومحرر ومخزن وقراءة وجدولة وتنفيذ واختبار migration واضحا.

تحتوي التطبيقات على قواعد التحكم والتحقق والمحاكاة واستخدام الأداة وخدمة أوامر الأتمتة، MCP/A2A/REST/Binder، ومخزن أسرار وكتالوج موفّرات ونماذج. الإعداد الحالي لمنح الوصول الخارجي ثنائي ويعطي full access دائما بعد اقتران صريح. احفظ ذلك العقد كما هو؛ أضف موافقات أكثر دقة إلى تعريف الوكيل الداخلي الجديد، مع واجهة توضح الفرق بين كليهما.

المحادثة تقيد الجولات إلى 8 وطلبات الأدوات إلى 16 في الجولة، ومدتها إلى 45 ثانية لطلب الموفّر، والرسائل إلى 128، والنص إلى 131072 حرفا والمخرجات إلى 65536 حرفا. لا تكفي هذه القيود وحدها لتحديد إجمالي التكلفة أو مهلة الأدوات أو استرجاع التشغيل بعد موت العملية. AiAgentTraceRecorder موجود، لكن التسجيل الفعلي لا يعد قابلا للعرض حتى يحقن ويوصل ويختبر.

محرر العقدة القانونية الحالية يسمح بعناصر Boolean وEnum وSecret read-only؛ الأنواع الأخرى محررات نصية عامة، والاختيارات والمساعدة والترجمة ليست موحدة تماما. توجد محررات خاصة للوقت والتاريخ والموقع والحزم والحقول المتقدمة؛ احتفظ بها حتى تنفذ بدائل parity.

## 4. تجربة المستخدم المطلوبة

شاشة قائمة الوكلاء تتيح البحث والفرز حسب حالة النشاط والموفّر وآخر تشغيل. لكل تعريف صفحة تبويب: الهوية والمهمة، النموذج والاتصال، الأدوات والبيانات المسموحة، الموافقات، الجداول والمحفزات، الحدود، الذاكرة، وسجل التشغيل. مساعد الإعداد ينشئ مسودة ويشرح اعتماد كل قدرة واختبار اتصال الموفّر قبل التمكين. ميزات النسخ والاختبار في وضع تجريبي لا تنشئ تعديلات حية بلا تأكيد.

لكل وكيل نموذج أولي بلا تجاوز للصلاحية: الاسم والوصف ومطالبة نظام بإصدار وموفّر اتصال ونموذج مرجعي وسياسة أدوات وخصوصية ومستويات مخاطر وحدود للوقت والجولات والرموز/التكلفة ومنبه تشغيل واحتفاظ. إمكانية الموفّر تختار من سجل القدرات المحدث لا من نص النموذج.

محرر المحفزات والإجراءات يعرض المجموعات ثم الأنواع المدعومة للمستخدم على جهازه. الحقول لكل نوع لها عنوان مترجم ومساعدة وأمثلة ووحدات وقواعد لازمة/اختيارية وظهور شرطي وإعداد افتراضي ومحرر مناسب ومصدر اختيار وتجربة تحقق؛ وتظهر الحالة من النظام والمزوّد. تعرض الشاشة قدرة كل نوع على: متاح، يتطلب صلاحية، دور نظام، عتاد/مرافق، Shizuku/Root/مالك جهاز، أو غير متاح، ولا تسمح تمكين نوع unknown. حفظ المسودة واستعادتها بعد إغلاق الشاشة من دون فقد أو كشف سر.

## 5. المعمارية والعقود

أنشئ core:agent-runtime كوحدة مستقلة عن Compose وapp؛ تعتمد على ai-runtime وautomation-control وdomain، وتعبر إلى التنفيذ عبر أدوات محددة وخدمة الأوامر. تضيف feature:agents واجهة التطبيق. app/data يركب Room ومزوّد Android والشبكة والتشغيل. لا يملك Adapter التخزين أو المنبهات أو عمليات Root، ولا يتخطى CapabilityRouter.

النماذج الأساسية: AgentDefinition + revision، AgentPolicy، AgentBudget، AgentRun، AgentRunEvent، AgentApproval، AgentMemoryEntry. يملك repository المعاملة وتعارض المراجعة. لا تضم التعريفات مفاتيح API. استخدام الاتصال يحيل إلى secret reference في المخزن الحامي الحالي. أثر الأداة يستعمل فهرسا ثابتا ومراجعات definition/policy/automation. سياسة الوكيل تتضمن tools/scopes/data allowlists، مبدئي AUTO_READ_ONLY وCONFIRM_WRITES، وسقوف الحجم والزمن والمحاولات. الموافقة تُربط بالوكيل وتعريفه وسياسته والجهاز والفعل المحدد/نسخته/مدخلاته الحساسة ووقت انتهاء مع منع replay؛ لا تقبل عند تغير أي مكوّن.

كل تشغيل ذو حالات versioned، وdeadline واحد يحيط بالنموذج والأدوات، وإلغاء يصل لمصدر العمل، وidempotency/concurrency limit وميزانية تحقق ذرية. سجل التشغيل redacted ولا يحفظ رسالة شخصية أو سر افتراضيا. عند استعادة التطبيق تنفذ استعادة تصنيف الحالة مرة واحدة؛ العملية غير idempotent لا تعاد قبل المصالحة أو موافقة جديدة. الذاكرة scoped للوكيل والمحادثة، اختيارية محدودة العمر مع عرض وتعديل وتصدير ومسح وعزل متقاطع. تعامل البيانات الخارجية كبيانات غير موثوقة وتمنع تحويلها آليا إلى تعليمات النظام.

يفحص المنفذ مخطط وسياسة الأدوات لكل استدعاء، ثم يمر التعديل عبر AutomationCommandService مع تحقق وdry-run وإعادة فحص revision وقدرة لحظية قبل كل أثر. يقلص audit وتفسير رفض السياسة. كل شيفرة سرية تمر بإشارة سرية لا قيمتها النصية؛ لا توجد قيمة سر في prompt أو database أو SavedState أو navigation أو log أو trace أو backup عادي.

عقد محفزات الأسر التي يلزم دعمها:
- Event: occurrence ID وtimestamp ومصدر وحمولة typed وسياسة duplicate/replay والاحتفاظ والخصوصية؛ لا يحتفظ بحدث مؤقت كحالة دائمة.
- State: true/false/unknown ومصدر القراءة/تاريخها ودخول/خروج وسياسة القيمة الأولية.
- Threshold: مقارنة ووحدة وحدود وهسترة واستقرار وعينات وسياسة فقد المستشعر.
- Schedule: المنطقة الزمنية/DST والتكرار والنافذة والدقة الفعلية أو التقريبية والتعويض عن الوقت المنقضي وإعادة الإقلاع.
- External/provider: هوية ومصادقة وحد payload/replay ومهل وإعادة محاولة وصحة الخدمة/الاتصال.

تبقى ANY/ALL الحالية لها دلالة وقوع حالي وحالة حية. لا يترجم ALL تلقائيا إلى تسلسل تاريخي. عقد التتابع A ثم B يحتاج DSL بإصدار مستقل يعبر عن المدة والمحو وإعادة التشغيل. عقد الإجراء تصرح بالهدف/الترتيب والإدخال الافتراضي والوحدات والتعبير والإخراج والمهلة والإلغاء وretry/idempotency والتعويض وإثبات الإكمال ومتطلبات الأجهزة. تسليم Intent يثبت قبول التسليم فقط.

مسار الكتالوج القانوني يضاف بعد ذلك: stable target/operation/predicate keys، تعريف نسخ ومخطط وإدخال ومخرج وmetadata عرض وقدرة، repository typed يحفظ معرّف النوع بلا تعداد، migration وbackup صيغة versioned، registry مراقبات للمحفزات وhandler يمر بالـplanner/router/dispatcher. قدم مثالا end-to-end عقدة تجريبية غير قديمة وحذفها/تحديثها قبل فتح التسجيل لعائلات جديدة. ثبّت تماثل بين catalog/schema/compiler/runtime والواجهة وAPI.

## 6. مصفوفة العائلات المقترحة

هذه فرص تطوير، ليست ادعاء دعم الآن: الوقت/التقويم والاستثناءات، فلاتر الشبكات/المحتوى، Bluetooth وBLE وNFC/USB، سياج مكاني ومدة/نشاط وحركة، خمول وحرارة ومعدل الشحن، صوت/مخرج ودور الشاشة، نشاط التطبيق والتثبيت/الإصدار، مرشح الإشعار وقناته وإجراء الرد الذي أتاحه التطبيق، مكالمات/SMS واختيار SIM وعرض مقابل إرسال، ملفات عبر URI يمنح الوصول، HTTP وwebhook ومصادقة سرية، تحويل ومعالجة البيانات والذاكرة، متغيرات وتدفقات شرطية ومهلة/إلغاء workflow، محرك ومساعد Wear/desktop، home integrations لكل connector فعلي، وصولية وROM/device-policy عبر حدود معرّفة، ودعوة AI محددة schema.

لكل اقتراح مؤشر متطلبات المصدر والواجهة والمدخل الافتراضي والمخرجات والحالات الطرفية والتوافر المنفذ. أضف صفا فقط إذا استكملت عملية من العقد إلى التخزين إلى العرض/التحقق إلى الجدولة والتنفيذ والرصد مع unit/instrumented/device gates. التسلسل: مفهرس قدرات ومدقق مخطط، تخصيص UI وإرشاد الصلاحيات، أنواع محلية منخفضة المخاطر، مراقبات عامة، إجراءات بالـAPI العام، connectors/companion ثنائية الاتجاه، privileged/OEM بعد أدلة فعلية.

لا تعلن API عامة عن الكتابة أو توقيت أو واجهة ليس لها ما يدعمها. بالذات تشغيل wifi أو Bluetooth أو DND أو مكالمات أو clipboard أو إشعار أو location الخلفي أو الوصول للملفات قد يعتمد على إصدار Android، إذن وقت تشغيل، دور، إعداد نظام، شريك أو OEM، ومواعيد الخلفية الدقيقة لها قيود النظام. التطبيق يوضح المتاح مع السبب وبديل آمن بدل وعد شامل. ملفات النظام تقتصر على URI صلاحه صرح به المستخدم.

## 7. الأمان وإمكانية الوصول والمقاييس

كل محرر RTL/عربي وإنجليزي، يعمل TalkBack وتكبير النص واختبار دوران/استعادة وkeyboard، يربط الخطأ بمفتاح الحقل لا قيمته، ويعرض أي قوائم أو عناوين واختيارات مترجمة. أحداث الواجهة غير مباشرة أثناء تنفيذ tool approval/audit.

الرفض متعدد الأسباب وfails closed للقدرة المجهولة. المصادقة لا تمنح إذنا خارج سياسة التعريف. الالتزامات تشمل endpoint/DNS/replay/rate/input bounds، تسجيل redacted، توقيعات relay، process-death and revoke, lock/restart and duplicate launches، migration restore، وadversarial provider tests. تتضمن تكلفة/رموز/وقت ومصدر سعر مؤرخ/صريح، وإلا توسم التكلفة غير متاحة. تتبع الأداء وقت فتح قائمة الكتالوج وتحرير حقل typed وزمن المحفز ومعدل التنبيه واستهلاك battery والعمل المكرر ومخرجات process kill. قيس عبر Android versions وpermission/privilege states وشركاء/OEM فقط إذا الأجهزة موجودة.

مصفوفة الإطلاق تصنف لكل قدرة: VERIFIED_LOCAL, IMPLEMENTED_UNVERIFIED, PUBLIC_API_PERMISSION_REQUIRED, COMPANION_REQUIRED, PRIVILEGED_BACKEND_REQUIRED, UNAVAILABLE_CURRENT_DEVICE, UNSUPPORTED. لا يساوي mock أو emulator نتيحة هاتف فعلي.

## 8. القبول الكامل

1. إنشاء وتعديل وتعطيل وحذف وكيلين لا تتداخل هويتهما أو أدواتهما أو ذاكرتاهما بعد قتل العملية.
2. كل رفض أداة/حقول/صلاحيات/حدود يحدث قبل أثر جانبي؛ الأدوات المرجعية تحاكي وتتطلب الموافقة عند طبقة كتابة. الموافقة القديمة تتوقف عند أي مراجعة أو تغير جهاز أو معاملة.
3. budget وتباطؤ الموفر وحدود الوقت وإعادة المحاولة والتعافي قابلة للإظهار. يثبت اختبار انقطاع التطبيق قبل/بعد فعل side-effect عدم تكرار mutation.
4. إلغاء التشغيل يوقف الموفّر وكل أداة مملوكة وينشئ audit terminal مرة واحدة. عزل memory/tool/prompt يمنع عابرا بين الوكلاء.
5. محرر حقل لكل نوع قانوني يعيد save/load مع validation الواضح وتغطية TalkBack/RTL. capability matrix توضح غير المدعوم.
6. العقد canonical الجديدة تمر من الإنشاء والتخزين والترحيل/backup والمحاكاة والجدولة والتنفيذ وإعادة التشغيل باستخدام معرف ثابت بلا إضافة enum.
7. لكل trigger/action اختبار نجاح وفقد صلاحية/موفّر/عتاد/بيانات سيئة/timeout/cancel/duplicate والحدود المهمة. تحفظ الأنواع القديمة 57/176 golden parity، وتضاف الأنواع الجديدة إلى سجلها كعقود مستقلة قابلة للتدقيق.
8. كامل Gradle CI gates والـcanonical contract/migrations/secrets/build/R8/test/release; instrumented Android permissions and process-death. أجهزة فعلية ذات OEM مختلفة قبل إثبات behavioral coverage.

## 9. محطات التنفيذ

### A. إغلاق فرع atomic
أكمل T20 routing وhealth، T21 UI consistency، T22 baselines منقولة، T23 device matrix، T24 CI consolidation، T25 fault injection، T26 full regression، T27 docs, T28 audit. مرجع الخطة القائمة في plans/2026-10-01-atomic-stability-ai-provider-overhaul.md. أصلح أولا النقل في OpenAI Responses/Gemini function calling ومسار verify profile الأصلي. كل إصلاح يحتاج regression + CI مشيرا إلى commit.

### B. قدرة تخصيص العقد
أنجز typed editors للحقول boolean/enum/number/duration/time/date/location/package/URI/JSON/list/select/secret reference/expression، error parser وdefault/visibility/units/locales وlist picker. اربط label/key ثابت بالمترجم. اكتب UI save/reload/capability/incompatible permission tests.

### C. agent domain/contracts
أنشئ core:agent-runtime ومخططات/norms واختبارات pure Kotlin للسياق والـpolicies/التراخيص/الانتقالات/budget وبلا Android dependencies. حدد channel schema لكل event.

### D. persistent storage/recovery
أضف جداول حسب نمط DB وترحيل schema إلى versioned state store agent definition/revisions/runs/events/approvals/memory. اختبر upgrade من أحدث production snapshot وإيقاف أثناء كل مرحلة وإصلاحية corruption واسترجاع/backup دون أسرار أو ادعاء atomic side effects.

### E. authoring/runtime security
أضف feature:agents definitions and profile selection/capability UI/test run، injectable policy-filtered tool executor وتأكيد، idempotency ledger/recovery، budget/deadline/cancellation، per-agent trace/memory. اختبر مصدر الأداة داخل app وMCP/Binder parity والرفض من سطحين على الأقل.

### F. end-to-end canonical extension
حل فصل typed canonical schema عن enum القديم ومطابق runtime/db/migration/export/import، ثم اختبر تعريف محفّز إجرائي جديد من schema إلى validator/planner/plugin or provider. لا تفتح موجة capability اعتمادا على migration doc وحده.

### G. موجات المخزونات
Wave 1: time/calendar/data/variable/notification filters تحسينات ضمن السلوك العام الحالي. Wave 2: network/app/files/communication بواجهات public ومدخلات URI/secret موثقة. Wave 3: BLE/NFC/USB/Wear/desktop/provider كتكاملات مرافق. Wave 4: accessibility/ROM/provider-owner/routine high-risk بحسب قدرة قابلة للملاحظة وإثبات fallback. Wave 5: AI tool/event داخل schema حدوده typed وموافقة وسقفها. سجلات لكل Wave تتبع التكلفة والصلاحية والمزامنة والترجمة والاختبار بالأجهزة.

### H. التحقق والإصدار
لكل موجة gate حديث complete + CI + اختبارات الهاتف ذات الصلة، اجمع event counts ومقاييس الأداء وحدود الأجهزة؛ حدث compatibility catalog وnotes/migration/release/unverified ledger. لا تعد إصدارها complete من test inventory أو عقد simulator.
