# Documentation index

The current guides below describe the integrated v3.74 candidate. Actual verification and publication status lives in [VALIDATION.md](VALIDATION.md). The source code and reproducible checks take precedence over an old report or plan.

Start with [the project README](../README.md), [capability catalog](CAPABILITY_CATALOG.md), [configuration](CONFIGURATION.md), [architecture](ARCHITECTURE.md), [security](SECURITY.md), [audit disposition](security-audit-2026-09-16-implementation.md), [comparison/roadmap](ROADMAP_2026.md), [required checks](REQUIRED_CHECKS.md) and [releasing](RELEASING.md).

Historical reports are preserved rather than rewritten as if their observations happened against today's code. Their banners explicitly withdraw any implication that old counts, completion assertions or device-test results certify the current release. Source-extracted options tables are useful inspection aids, not proof of exhaustive configuration coverage. New capabilities and their operational limits are documented in the current configuration reference.
