# بروتوكول قبول طرفي لأتمتة NexaFlow على Android 17

## الغرض والحدود

هذا البروتوكول هو اختبار قبول على **هاتف Android 17 حقيقي**؛ وليس بديلاً عن اختبارات الوحدة أو البناء. البيئة التي بُنيت فيها هذه المراجعة لا تحتوي جهازاً متصلاً، أو صورة محاكي Android 17، أو تسريع KVM. لذلك لا يمكن ادعاء تنفيذ اختبار طرفي حقيقي لتشغيل نقطة الاتصال أو تغيير نوع شبكة الشريحة أو منح Shizuku/Root من دون هاتف يملك هذه الخصائص.

> لا يمنح Android تطبيقاً عادياً صلاحيات `MODIFY_PHONE_STATE` أو التحكم بنقطة الاتصال. مسار تغيير نوع الشبكة يحتاج تثبيتاً مميزاً أو Root/Shizuku صالحاً، ويجب أن يسجل التطبيق فشلاً صريحاً عندما لا تتوفر القدرة بدلاً من نجاح زائف.

## بيئة القبول

| عنصر | شرط القبول |
|---|---|
| النظام | هاتف فعلي يعمل بـ Android 17 / API 37، مع آخر تحديثات الشركة المصنعة. |
| التطبيق | تثبيت `app-debug.apk` الناتج من الالتزام الجاري، فوق نسخة نظيفة أو بعد إزالة بيانات NexaFlow. |
| الوقت | تفعيل الوقت والمنطقة الزمنية التلقائيين أولاً، ثم تكرار اختبار تغير الوقت والمنطقة الزمنية. |
| البطارية | تكرار سيناريو الوقت مع وضع Doze ووضع توفير البطارية، ثم بعد تعطيل تحسين البطارية للتطبيق كاختبار ضبط. |
| اتصال الهاتف | شريحة فعلية نشطة لاختبار نوع الشبكة، ونقطة اتصال Wi‑Fi حقيقية لاختبار Hotspot. |
| امتياز التحكم | تنفيذ المسار مرتين: من دون امتياز للوصول إلى فشل واضح، ثم مع Shizuku أو Root حي وممنوح للتطبيق للوصول إلى نجاح مؤكّد. |

## حالات القبول الإلزامية

| المعرف | السيناريو | الإجراء | معيار النجاح والدليل المطلوب |
|---|---|---|---|
| E2E-01 | جدولة ليلية عابرة لمنتصف الليل | أنشئ مهمة تبدأ 22:00 وتنتهي 06:00، مع فعل مرئي عند البدء وفعل استعادة أو قيمة محددة عند النهاية. | ينفذ كل طرف مرة واحدة فقط. تظهر في السجل هوية البدء والنهاية ووقت التنفيذ الفعليان. |
| E2E-02 | Doze وإطفاء الشاشة | فعّل المهمة نفسها ثم اقفل الهاتف قبل الحدث، واختبر وضع Doze. | يستقبل النظام إنذار الوقت؛ لا توجد مطالبة بأن يبقى NexaFlow مفتوحاً. إذا أزيل إذن المنبهات والتذكيرات، تظهر حالة غير جاهزة بدلاً من «تمت الجدولة». |
| E2E-03 | إعادة التشغيل | جدولة حدثين مستقبليين، أعد تشغيل الهاتف، ثم افحص بطاقة المهمة والسجل. | تعاد جدولة نقطة البدء والنهاية بعد `BOOT_COMPLETED`، ولا تضيع مهمة مفعّلة. |
| E2E-04 | تغيير وقت/منطقة زمنية | بعد جدولة مهمة، غيّر الساعة والمنطقة الزمنية ثم أعدهما إلى الوضع التلقائي. | يعاد حساب الإنذار القادم ولا يحدث تنفيذ مزدوج أو تنفيذ في وقت منقضٍ. |
| E2E-05 | Hotspot ON/OFF | أنشئ محفز Hotspot ON ثم شغّل نقطة الاتصال من إعدادات النظام. أنشئ نسخة OFF ثم أوقفها. | ينفذ المحفز وفق رد نداء `TetheringManager` ولا يعتمد على مفتاح إعداد قديم أو اسم واجهة USB/Bluetooth. |
| E2E-06 | تغيير نوع الشبكة بلا امتياز | أنشئ فعل وضع الشبكة، ومن دون Root/Shizuku شغّله يدوياً ومن إنذار. | يفشل بوضوح مع السبب والقدرة الناقصة؛ لا تسجل السجل نجاحاً ولا تتغير الشريحة. |
| E2E-07 | تغيير نوع الشبكة مع امتياز | امنح Shizuku أو Root، اختر 4G/5G أو الوضع الذي تدعمه الشريحة، ثم تحقق من إعدادات النظام. | يتغير الوضع للشريحة الفعالة، وتثبت قراءة ما بعد التنفيذ النتيجة. تعود الاستعادة إلى اللقطة السابقة عند انتهاء المهمة إذا اختيرت. |
| E2E-08 | إلغاء امتياز/فقدان خدمة | أثناء وجود مهمة مفعلة، ألغ إذن Shizuku أو أوقف خدمته. | لا تتعطل العملية ولا تدّعي نجاحاً؛ تسجل حاجة إعادة منح الوصول. |
| E2E-09 | إعداد صوت خلفي | نفذ تغيير صوت أو رنين من إنذار مع التطبيق في الخلفية. | يتأكد السجل من قراءة القيمة بعد التنفيذ؛ إذا حظر Android 17 التغيير، تظهر نتيجة فشل قابلة للتصرف بدلاً من نجاح زائف. |
| E2E-10 | إذن المنبهات الدقيقة | ألغ «المنبهات والتذكيرات»، احفظ مهمة وقت، ثم امنح الإذن من النظام. | لا يغلق المحرر قبل عرض الطلب. بعد المنح يعاد تسليح الإنذار ويتحول وضع المهمة إلى جاهز. |
| E2E-11 | اتصال محلي HTTP | نفذ طلب HTTP إلى عنوان LAN مع منح `ACCESS_LOCAL_NETWORK`، ثم بعد سحبه. | ينجح عند المنح؛ وعند السحب يفشل الطلب بوضوح، بينما يظل طلب إنترنت عام غير متأثر. |
| E2E-12 | إطلاق واجهة من الخلفية | شغّل أفعال فتح تطبيق/إعدادات/URL من إنذار والهاتف مقفل، ثم من تفاعل إشعار مستخدم. | لا يسجل محرك التنفيذ نجاحاً مضللاً إن حظر النظام الإطلاق الخلفي. ينجح المسار الذي يبدأه نقر المستخدم. |

## أوامر جمع الدليل

نفّذ الأوامر الآتية من جهاز تطوير موصول بالهاتف، مع استبدال اسم الحزمة إذا اختلف. لا تنشئ هذه الأوامر امتيازات التطبيق؛ بل تجمع أدلة فقط.

```bash
adb devices -l
adb logcat -c
adb logcat -v threadtime | grep -E "NexaFlow|AudioHardening|ActivityTaskManager|AlarmManager"
adb shell dumpsys alarm | grep -i nexaflow
adb shell dumpsys activity services | grep -i nexaflow
adb shell cmd appops get com.nexaflow
```

لاختبار تقسية الصوت في Android 17، استخدم الاختبار الرسمي فقط على جهاز غير إنتاجي:

```bash
adb shell cmd audio set-enable-hardening throw
# نفّذ E2E-09 ثم افحص logcat
adb shell cmd audio set-enable-hardening disable
```

## قرار الإصدار

يقبل الإصدار فقط إذا حققت الحالات E2E-01 إلى E2E-10 مع أدلة زمنية وسجلّات واضحة على الجهاز المستهدف. الحالات E2E-11 وE2E-12 مطلوبة إذا كانت مهام HTTP أو فتح الواجهات جزءاً من الإصدار. أي اختلاف OEM أو رفض صلاحية يجب أن يسجل كـ **قدرة غير متاحة** أو **فشل صريح**، وليس نجاحاً.
